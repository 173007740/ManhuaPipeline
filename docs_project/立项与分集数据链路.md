# 立项与分集：底层数据链路（防忘手册）

这份文档记录「立项 → 分集 → 逐集跑剧本」这条链在库里怎么落、agent 怎么读。
凡是涉及改这条链，先看这里，再动手。

最后更新：2026-10-01（v1.29.42 · 立项结果落到漫剧那一行）

---

## 一、业务流程（业务口径，不是代码推断）

```
立项 = 创建漫剧 Dramas
        │  跑一次 P0（立项）
        ▼
   产出「N 集分集卡点 + Cliffhanger」
        │  解析 → 分集提纲
        ▼
   生成 N 个集项目 Projects（一集一个，12 集 = 12 行）
        │
        ▼
   打开任意一集：/pages/skill-studio.html?projectId=57&dramaId=25
        ├─ 「项目立项」那一格显示立项结果，左侧菜单打勾
        └─ 点「剧本生成」→ 跑 P1 → 生成**这一集**的剧本
```

要点：
- **立项是漫剧级的**，整部一份，12 集共用。
- **集 = Projects 表的一行**，一集一个项目。**项目下不再有多集**（`Episodes` 表是老模型的遗留，新流程不往那儿落）。
- 立项结果每一集都要看得到，且显示的内容对所有集一致（+ 本集自己的那条提纲）。

## 二、数据层级与表

| 层 | 表 | 说明 |
|---|---|---|
| 作品 | `Works` | 最上层容器 |
| 漫剧（立项） | `Dramas` | **立项就挂这一层**：画幅、题材、集数、角色、提示词引擎，以及立项结果 |
| 集（项目） | `Projects` | `DramaId` 指向所属漫剧，`EpisodeNumber` 是第几集 |
| 老剧集 | `Episodes` | 老模型「项目下多集」的遗留，新流程不用 |
| 运行 | `DirectorSkillRuns` | 一次运行的头：`PackId / ProjectId / EpisodeId / DramaId / InputsJson / CurrentStage / Status` |
| 步骤 | `DirectorSkillRunSteps` | 每一步：`InputText / OutputText / OutputJson / DocsSummary / Gates / Status / ImportedCount / ImportError / ConfirmedAt` |

立项相关的列（`Dramas`）：

| 列 | 用途 | 来源 |
|---|---|---|
| `Status` / `Aspect` / `Delivery` / `Genre` / `ArtStyleId` / `Hook` / `Premise` / `Platform` / `EpisodeCount` / `EpisodeDuration` / `CharactersJson` | 立项表单填的通用参数 | 立项表单 → `PUT /api/director-agent/brief` |
| `PromptEngine` | 提示词引擎 SD / H3，P4 直接读这一列 | 同上 |
| `EpisodeOutlineJson` | 分集提纲（**JSON 大字段，历史遗留**） | P0 跑完解析后写入 |
| `P0OutputText` / `P0StepId` / `P0FinishedAt` | **立项结果**（v1.29.42 新增） | P0 跑完写库，见下 |

## 三、立项结果为什么曾经没有落点（根因）

agent 入库的唯一入口只看 `(ProjectId, EpisodeId)`：

```csharp
// Services/DirectorAgentService.cs
var ctx = _db.GetRunContext(runId);
var res = _importer.Import(stage.OutputTarget!, json, raw, ctx.ProjectId, ctx.EpisodeId, ...);
```

而 **P0 跑在漫剧上**：`CreateSkillRun(..., dramaId: id)`，那时一个项目都还没建，`ProjectId` 是 NULL
→ `ImportDeliverable` 在 `projectId<=0` 时直接返回
→ **P0 是唯一产出不落业务表的阶段**，原文只剩 `DirectorSkillRunSteps.OutputText`。

于是每一集要显示立项结果，只能回头翻运行、翻步骤，还得跨到「哪一集跑了 P0」那条运行史里找。
后面所有绕路（跨集找 StepId、JSON 大字段 + OPENJSON）都是这一条推出来的。

**结论：立项结果该跟画幅、集数一样，存在 `Dramas` 那一行。**

## 四、现在的落点与读写（v1.29.42 之后）

### 写
- `DramaController.GenerateEpisodes`（跑立项）：`RunStepAsync("P0")` 返回后立刻 `SaveDramaP0Result(dramaId, stepId, output)`，**产出先落住再解析分集表**。
- `DramaController.ParseEpisodes`（重解析）：同样写一份。
- 脚本 `Database/Upgrade_立项结果落库.sql`：补三列 + 回填老数据（可重复执行）。

### 读
- `DbService.GetDramaP0Result(dramaId)`：一次读出 `(StepId, OutputText, FinishedAt)`。
- `GET /api/director-agent/shared-step?dramaId=25&stageKey=P0`：优先读 `Dramas` 那一行；查不到才回退到按运行翻（老数据未回填时）。
- 前端 `skill-studio.html`：`DRAMA_ID` 取自 URL，`loadSharedStep()` 拿到 stepId 后把「项目立项」那一格标 done 并允许看产出；卡片标注「漫剧级，整部共用」。

### 页面上的样子
- 打开第 1 集 `?projectId=57&dramaId=25` 和第 2 集 `?projectId=58&dramaId=25`，立项那一格**看到的都是同一份**。
- 不再显示「第 N 集跑的」（立项不属于任何一集）。

## 五、agent 跟底层怎么咬合

### 5.1 引擎不认识业务
`DirectorAgentService` 只做四件事：取规则、拼 prompt、调 LLM、存结果。
跑哪几步、每步产出进哪张表，全在库里：`DirectorSkillStages.OutputTarget`。

| StageKey | OutputTarget | 落点 | 覆盖方式 |
|---|---|---|---|
| P0 立项 | `deliverable` | 交付物表（**项目未建时不写**）+ `Dramas` 立项结果 | 追加 Version+1 |
| P1 剧本 | `deliverable` | 交付物 + `ScriptDrafts` + `Projects.ScriptContent` | 交付物追加；ScriptContent 覆盖（旧版先另存） |
| P2a 资产 | `assets` | 四张资产表 | 整项目清空重建 |
| P2b 台账 | `deliverable` | 交付物 | 追加 |
| P2c1/2/3 | `asset_prompts` | 回填已有资产卡的提示词列 | 覆盖（不新建资产） |
| P2d 图册 | `deliverable` | 交付物 | 追加 |
| P3 分镜 | `frames` | `StoryboardFrames` | 按单元删除重写 |
| P4 提示词 | `prompts` | `SeedancePrompts` | 按镜头原地覆盖（保留参考图绑定） |
| P5 质检 | `deliverable` | 交付物 | 追加 |

### 5.2 agent 读立项的三个注入点（`ExecuteStepAsync`，P0 自身除外）

1. **引擎**：`Dramas.PromptEngine`（经 `GetDramaIdByProject` 上溯）→ 决定 P4 走 SD 还是 H3；没填才回落到运行级 `InputsJson` 的 `promptType`。
   `Services/DirectorAgentService.cs:401`
2. **【立项锁定参数】**：优先取本运行 P0 步骤的 `InputText`；没有就 `GetRunDramaId → BuildP0InputText(did)` 用漫剧那行合成，并声明「优先级高于任何上游产出」。
   `Services/DirectorAgentService.cs:423-446`
3. **【本集提纲】**：`GetEpisodeOutlineForProject(projectId)` 按集号取本集那条（标题/三幕骨架/卡点），喂给模型，保证第 2 集写的是第 2 集的事。
   `Services/DirectorAgentService.cs:448-470`

改这条链时，这三处的语义不能变；变的只允许是「从哪儿读」。

## 五之二、点「生成」时，后端怎么知道是第几集

**只有 URL 上的 `projectId` 一个参数，不需要额外传集号。**
集号不是传进来的，是 `Projects` 表上那一行自带（`EpisodeNumber`）。

完整一跳：

1. 打开 `skill-studio.html?projectId=58&dramaId=25`
   → `applyPreset()` 把 58 填进 `#proj` 下拉并触发 change（`skill-studio.html:729`）。
2. 点「生成」→ `doStep()` → `ensureRun()` → `POST /api/director-agent/runs`，body 带 `projectId: 58`
   → `CreateSkillRun(packId, 58, ...)`（`DirectorAgentController.cs:99`）。
3. → `POST /runs/{id}/run-all` 同样带 `projectId: 58`
   → `RunFromAsync(..., body.ProjectId, ...)` → `UpdateSkillRunTarget(runId, 58, null)`，运行绑到项目 58。
4. 每一步执行时，`GetRunContext(runId)` 拿回 `ProjectId = 58`，三处用它：
   - **本集提纲**：`GetEpisodeOutlineForProject(58)` → `Projects` 表查到 `EpisodeNumber=2, DramaId=25`
     → 取提纲里 `episodeNumber=2` 那条 → 注入【本集提纲·第2集】。
   - **立项参数**：58 上溯 `DramaId=25`，读漫剧那一行（引擎 `PromptEngine`、立项锁定参数）。
   - **产出落点**：`Import(..., projectId: 58, ...)` → 剧本写进项目 58 的 `ScriptContent` + `ScriptDrafts`。

`dramaId` 是给**立项那一格和立项表单**用的（按漫剧读那一份结果），生成剧本时后端自己从 58 上溯，前端传它只是省一次查询。

实例（库里现状）：`Projects 58 → DramaId 25, EpisodeNumber 2, 标题「靛蓝的指纹」`，与漫剧提纲里第 2 集标题一致。

注意点：
- `#proj` 必须有值，否则按钮提示「先选好落点项目」。
- 浏览器里记着的 runId 只在 `d.projectId === 当前 projectId` 时才接（`skill-studio.html:1858`），不会把第 1 集的运行接到第 2 集。
- 项目若没有 `EpisodeNumber`（手工建的），`GetEpisodeOutlineForProject` 返回 null → 不注入本集提纲 → 模型会照立项自己编故事。分集提纲建出来的集（57~68）都有集号。

## 六、铁律（踩过的坑）

1. **不建视图。** 数据取不到/对不上，一律「缺表补表、缺字段补字段」。
2. **底层错就改底层。** 不要用查询胶水（跨集翻运行、SQL 里 `OPENJSON` 挖 JSON、二选一 OR）去补结构缺陷——那只会让系统越来越复杂。
3. **先说清现象，再动手。** 拿不准就先把「写入端 / 读取端 / 落点」摆出来。
4. 每次改完：编译 → 跑升级脚本 → `git commit` → `VersionLogs` 插一条（Author = `AI`）。
