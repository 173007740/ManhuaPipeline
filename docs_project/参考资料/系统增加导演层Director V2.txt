OK 那我们升级 Director V2

可以。Director V2 的核心不再是“生成导演意图”，而是建立导演闭环：生成 → 校验 → 纠偏 → 重生成。

V1.5 解决的是“打斗怎么打不再让分镜乱编”；V2 要解决的是“分镜有没有真的执行导演要求”。

所以 V2 的主链应该升级成：

Unit
↓
DirectorPlan
↓
ActionPlan
↓
CombatGrammarEngine
↓
CombatBeats
↓
Storyboard
↓
DirectorValidator
↓
PASS？
├─ YES → 进入后续资产/提示词阶段
└─ NO  → 生成 ViolationReport
          ↓
        定向返工当前 Unit
          ↓
        再次校验

这一步一旦做完，你的 Director 才真正从“建议层”变成“控制层”。

V2 我建议重点做 4 个东西。

第一，新增 DirectorValidator。不要让它一上来就判断“镜头美不美”，先校验硬约束。第一版至少检查这些：

主体一致性
CombatBeat 覆盖率
CombatBeat 顺序
回合数
关键动作结果
胜负关系
核心爽点是否落镜
关键对白是否遗漏
VFX 峰值位置
角色能力越权
场景/角色资产是否错用

例如 DirectorPlan 要求：

PrimarySubject = 林烬
RoundCount = 3
VfxPeakPhase = Final
EndingState = 六名弟子被震退

结果 Storyboard 生成成：

Round1：围攻
Round2：林烬直接爆气结束

Validator 应该直接给：

{
  "passed": false,
  "score": 62,
  "violations": [
    {
      "code": "ROUND_COUNT_MISMATCH",
      "expected": 3,
      "actual": 2
    },
    {
      "code": "COMBAT_BEAT_MISSING",
      "beatId": "beat_03"
    },
    {
      "code": "VFX_PEAK_TOO_EARLY"
    }
  ]
}

第二，新增 ViolationReport，这个非常重要。不要只返回“失败”。

建议结构：

public class DirectorViolation
{
    public string Code { get; set; }


    public string Severity { get; set; } // Error / Warning


    public string Message { get; set; }


    public string Expected { get; set; }


    public string Actual { get; set; }


    public string CombatBeatId { get; set; }


    public string ShotId { get; set; }


    public string RepairInstruction { get; set; }
}

这样系统知道到底错在哪里。

比如：

ERROR
COMBAT_BEAT_MISSING


Beat:
B03


要求：
林烬近身反击第二名敌人


实际：
Storyboard 未出现


修复：
在 Shot 07-09 之间补充该 Beat，
不得改变 Beat04 的高潮顺序。

第三，不要失败后“整段重新随机生成”。这会很浪费。

V2 应该开始做：

定向返工。

比如只有 Beat03 漏了，就告诉 Storyboard LLM：

保留以下镜头：
Shot01
Shot02
Shot03
Shot04
Shot05
Shot06
Shot10


仅修复：
CombatBeat B03 缺失


要求：
在 Shot06 和 Shot10 之间补充 1-3 个镜头，
表现林烬近身切入、肘击、格挡第二人。
不得修改其他 CombatBeat。

这样系统稳定性会明显提升。

第四，引入一个 DirectorComplianceScore。

建议 100 分制，先不用太复杂，例如：

CombatBeat Coverage       30
Primary Subject            15
Combat Logic               20
Dramatic Purpose           10
Core Payoff                10
VFX Rhythm                  5
Dialogue                     5
Continuity                   5

低于比如：

80 = FAIL
80-89 = PASS WITH WARNING
90+ = PASS

但要注意：

某些错误不能靠总分掩盖。

比如：

主角错了
胜负结果错了
漏掉核心 CombatBeat
角色用了不存在的能力

这些属于 HardFail，即使总分 95 也不能通过。

所以你最好有：

public class DirectorValidationResult
{
    public bool Passed { get; set; }


    public bool HasHardFailure { get; set; }


    public int Score { get; set; }


    public List<DirectorViolation> Violations { get; set; }
}

然后 V2 的 Validator 不应该全部靠 LLM。

建议做成两层：

DirectorValidator
│
├─ RuleValidator
│   └─ 程序检查
│
└─ LlmValidator
    └─ 语义检查

程序能检查的坚决不要交给 LLM。

例如这些都可以代码直接查：

Beat 是否全部存在
CombatBeatIndex 是否连续
PrimarySubject 是否出现
RoundCount 是否正确
GrammarId 是否合法
角色ID 是否存在
技能是否属于角色
VFX Asset ID 是否存在
结局状态是否正确标记

这些才适合 LLM：

核心爽点有没有真正表现出来
情绪曲线是否成立
镜头是否突出主角
是否有“明明说压迫但镜头毫无压迫感”
动作因果是否自然

所以完整的 V2 结构我建议是：

DirectorPlan
↓
ActionPlan
↓
CombatBeats
↓
Storyboard
↓
RuleValidator
↓
LLM Semantic Validator
↓
ValidationResult
↓
RepairPlanner
↓
Storyboard Repair
↓
Revalidate

这里再加一个很重要的限制：

最多返工 2 次。

不要无限循环。

比如：

Attempt 1
↓
FAIL


Repair 1
↓
FAIL


Repair 2
↓
仍 FAIL


→ 使用当前最高分版本
→ 标记 NeedsReview
→ 继续流水线

否则很容易把 Stage 卡死。

你可以直接把下面这段交给 DeepSeek 作为 V2 开发任务：

Director V2 开发目标：


1. 新增 DirectorValidator。
2. Validator 分为 RuleValidator 和 SemanticValidator。
3. RuleValidator 使用程序规则校验：
   - PrimarySubject
   - CombatBeat 覆盖率
   - CombatBeat 顺序
   - RoundCount
   - EndingState
   - CombatGrammarId 合法性
   - Character/Skill/VFX Asset 合法性
4. SemanticValidator 使用 LLM 判断：
   - DramaticPurpose 是否落实
   - CorePayoff 是否成立
   - EmotionCurve 是否体现
   - CameraStrategy 是否服务主体
   - VfxStrategy 是否符合强度曲线
5. 新增 DirectorValidationResult：
   Passed
   HasHardFailure
   Score
   Violations
6. 新增 DirectorViolation：
   Code
   Severity
   Expected
   Actual
   CombatBeatId
   ShotId
   RepairInstruction
7. HardFail 类型至少包括：
   - PrimarySubject 错误
   - 核心 CombatBeat 缺失
   - 胜负结果错误
   - 关键角色能力越权
8. Storyboard 校验失败时，不默认整 Unit 随机重生。
9. 新增 RepairPlanner，只针对违规 Shot/Beat 定向修复。
10. 修复后重新执行 Validator。
11. 最大修复次数设为 2 次，超过后保存最高分版本，并标记 NeedsReview。
12. 新增 DirectorComplianceScore，满分100。
13. 当前版本禁止重构现有 Stage，Director V2 仍作为“分集细化 → 分镜 → 后续资产”的中间控制层。

V2 的最终验收标准也很明确：

同一个 Unit 即使分镜 LLM 第一次生成偏了，系统最终也能自己发现“哪里没听导演”，并把它纠回来。

V1 是“导演会说”，V1.5 是“武指开始听导演”，V2 就是“导演开始验收片场结果”。

做到这一步，你的系统就已经不是普通的 AI 分镜生成器了，而开始具备真正的“导演闭环”。
