最好的方式不是让 LLM 自由设计打斗，而是采用：
模板决定动作与运镜，LLM 只负责把角色、场景、武器填进去。

当前系统虽然注入了分镜库和打斗库，但 Stage 5 得到的打斗模板主要是“名称、层级、时长、适用场景、节拍摘要”，完整动作、运镜和约束要到 Stage 9 才注入。因此 LLM 在分镜阶段仍有较大发挥空间：[StageController.cs (line 215)](D:\\CodexProject\\ManhuaPipeline\\ManhuaPipeline\\Controllers\\StageController.cs:215)。
推荐工作方式
Stage 4 打斗单元
→ 代码筛选匹配模板
→ LLM 只能选择模板 ID
→ 按模板节拍填入角色和场景
→ 校验动作、运镜、时长、连续性
→ 锁定 Stage 5 分镜
→ Stage 9 只扩写成视频提示词，不重新设计动作
1. 打斗模板必须结构化
不要只写这种抽象描述：
快—快—顿—重，镜头有冲击力。

应该明确到时间段：
模板ID：FIGHT_11_COUNTER_01
适用：双人近战、反击、11秒
参与者：A进攻，B防守反击

0–2秒：
动作：A从画面左侧突进，B原地架势防守
运镜：全景固定，轻微前推
结束状态：A进入攻击距离，B完成格挡准备

2–5秒：
动作：A横斩，B后仰闪避并侧步
运镜：中景横向跟随，保持人物完整肢体
结束状态：A招式落空，身体重心前倾

5–8秒：
动作：B抓住空档反击，命中A肩部
运镜：近景快速推近，命中瞬间短暂停顿
结束状态：A向右后方失去平衡

8–11秒：
动作：A落地稳住，B收招保持戒备
运镜：中景缓慢拉远
结束状态：双方重新形成对峙
每段至少要明确：
开始姿态
动作主体和承受者
动作方向
运镜方式
景别
结束姿态
下一镜头接续状态
禁止事项
2. 分镜库使用“原子指令”
一条指令只负责一件事，例如：
CAM_TRACK_SIDE：横向跟随角色移动，保持人物全身完整
CAM_IMPACT_PUSH：命中前快速推近，命中瞬间短暂停顿
SHOT_WIDE_ANCHOR：全景建立双方位置和空间方向
SHOT_REACTION_CLOSE：近景捕捉受击表情和身体反馈
TRANS_MOTION_MATCH：以上一镜头动作方向连接下一镜头
打斗模板只能引用这些固定指令 ID：
运镜：CAM_TRACK_SIDE
命中镜头：CAM_IMPACT_PUSH
收尾：SHOT_WIDE_ANCHOR
这样 LLM 不需要重新发明运镜。
3. 代码先筛选，LLM 后选择
不要把整个打斗库全部交给 LLM。代码应先根据以下条件筛选：
双人、多人或群战
徒手、刀剑、法术或追逐
5、11、15 秒
普通交手、压制、反击、高潮对决
是否释放技能
T3、T4、T5 阶段
室内、室外、狭窄空间或开阔场地
筛选出最匹配的 1–3 个模板后，LLM 只能从这些模板中选择，不能创建新模板。
4. 技能库负责视觉效果，不负责基础动作
建议明确分工：
打斗库：身体动作、攻防关系、节奏和命中反馈。
分镜库：景别、机位、运镜、转场和光影。
技能库：技能形态、颜色、释放过程和视觉特效。
LLM：把实际角色、武器、技能和场景填进模板。
例如：
基础动作：来自 FIGHT_11_COUNTER_01
运镜：来自 CAM_TRACK_SIDE + CAM_IMPACT_PUSH
技能效果：来自 SKILL_T4_FIRE_BLADE
角色替换：A=主角，B=敌人
技能不能覆盖动作逻辑。即使释放大招，也必须说明起手、释放、命中、受击和收招。
5. Stage 5 就要拿到完整模板
完整的：
ActionPrompt
CameraPrompt
ConstraintPrompt
时间节拍
开始与结束状态
应该在 Stage 5 分镜规划时就确定。
Stage 9 只负责把已确定的分镜翻译成 Seedance 提示词，不能重新改变动作、镜头和技能安排。否则 Stage 5 和最终视频提示词可能不一致。
6. 增加硬性校验
LLM 输出后由代码检查：
模板 ID 是否真实存在。
运镜 ID 是否来自分镜库。
各时间段总和是否等于 5、11 或 15 秒。
每段是否有开始状态和结束状态。
上一镜结束状态是否能连接下一镜开始状态。
是否出现角色瞬移、武器换手、方向反转。
T5 是否只出现在高潮镜头。
一个时间段是否塞入过多复杂动作。
命中镜头是否包含受击反馈。
是否擅自创造库外技能或运镜。
不合格时只让 LLM 修复错误字段，不重新生成整段打斗。
视频生成层面的关键原则
为了让 Seedance 更稳定：
一个时间段只保留一个主要攻防动作。
复杂连招拆成多个镜头，不要一句话写十几个动作。
明确左、右、前、后和人物相对位置。
每段都写清起始姿态和结束姿态。
运镜不要同时“推拉摇移环绕变焦”全部使用。
命中必须包含攻击、接触、受击反馈和落点。
大幅运镜时减少复杂肢体动作；复杂动作时让镜头相对稳定。
11 秒打斗通常用“建立位置 → 进攻 → 反击命中 → 收势衔接”最稳定。
核心就是：打斗库提供“动作骨架”，分镜库提供“摄像机骨架”，技能库提供“视觉皮肤”，LLM只做受控填充。这样结果会比现在单纯把库作为参考文本交给 LLM 稳定得多。
