# 漫剧流水线架构合并方案

> 日期：2026-09-16
> 对标对象：`short-drama-agent`（外部 Skill，路径 `F:\80 Agent Skill\short-drama-agent`）
> 状态：P0 已实施（2026-09-16），P1 及以后待排期
> 结论一句话：**不是推倒重来，是补中间层。现状"两头强、中间空"——下游资产/守卫和上游多集管理都强于对标对象，唯独缺"连续性表征层"。**

---

## 一、对标对象拆解

`short-drama-agent` 不是"21 节契约"，它由五件东西组成：

| 组成 | 内容 |
| --- | --- |
| 12 步强制工作流 | 分析 → 资产抽取 → 连续性表 → 出图 → **验收闸门** → 连续性分镜 → copy-ready 提示词 → 专业镜头语言 → 质感层 → 逐镜生成 → 剪辑指导 → 检查清单 |
| 21 节输出契约 | 顺序固定，不可调换 |
| 6 类资产 | `character` / `scene` / `prop` / `clue` / `ui_plate` / `keyframe`，每个带 `asset_id + acceptance_criteria + status` |
| 6 张连续性表 | 场景空间 / 角色连续 / 道具状态 timeline / 线索揭示 / 动作因果 / 转场动机 |
| 5 个 CHECKPOINT | `overwrite` / `paid generation` / `asset approval` / `destructive cleanup` / `ambiguous source` |

核心哲学一句话：

```text
asset state + character state + prop state + space direction
+ action cause + edit reason + forbidden changes
```

关键特征：

- **单集级**（episode），不是整季流水线。
- 产物是**生产文件**（JSON manifest + 分镜卡 + 提示词），不是"漂亮的分镜文字"。
- 每镜写成**状态机**：上一镜结束 → 本镜开始 → 唯一动作 → 本镜结束 → 下一镜衔接 → 禁止变化。
- 资产必须**逐类验收**（`approved` / `needs_regeneration` / `missing`）后才能进入付费视频生成。
- 生成顺序强制：`dry-run` → 单镜测试 → 小批量 `--skip-existing`。

## 三、诊断：两头强、中间空

```text
上游（强）          中间（空）                下游（强）
────────────────  ──────────────────────  ──────────────────
多集/整季流水线     空间方位 无             资产库 真库+真图
阶段化 + 进度日志   道具 timeline 无         出图队列 并发+抢单
导演层 V1-V4       线索揭示顺序 无          16 步后置守卫链
战斗骨架/运镜原子   每镜信息增量 无          StoryboardAutoFixer
技能归属/别名库     禁止变化字段 无          导演校验器 4 类
```

对标对象的 6 张连续性表，本质是把"连续性"变成**可校验的数据字段**；
现状的问题，本质是**规则活在提示词字符串与后置正则里，不活在数据结构里**。

两者是同一个病：

- 空间方位、道具状态、线索顺序、每镜信息增量——现在全靠 LLM 在提示词里"记得"，没有任何字段承载，所以失败时只能靠后置守卫**事后补**（守卫链 16 步里一大半是补字段）。
- 守卫能补"格式"，补不了"语义"。道具状态倒退（刀已落地又回到手里）这类问题，正则查不出来。

## 四、两个关键问题的结论

### Q3：创意构思 / 故事分析 / 全局蓝图 能否删掉？

**职能不能删，形态必须重做。**

- 对标对象完整保留了这 5 节（节 1-5），说明职能是刚需。
- 但它的做法是：**这 5 节与资产表、连续性表在同一个文档里一次生成**。
- 现状是 3 次独立 LLM 调用串联、产出自由文本 → 信息在传递中衰减，下游只能"越缺越多"（`漫剧系统.md` §2 原话）。

结论：**阶段 1 / 2 / 3 号保留**（阶段号是持久化 ID），改为**一次调用产出三阶段内容、分别入库**，产物结构化为节 1-5 的字段形态。

### Q4：分集细化（阶段 4）是否多余？

**不多余，但它把两层压成了一层。**

- 对标对象把"节 10 动作因果表（抽象因果单元）"与"节 16 视频镜头任务卡（2-4 秒视频单元）"**分成两层**。
- 现状阶段 4 把这两层压成一层，直接产出视频单元。
- 这就是它提示词臃肿（5 段铁律 + 后置修复）的根因：**同一段提示词要同时完成"拆因果"和"定视频规格"两件事**，两套约束在互相打架。

结论：阶段 4 保留，但**显式拆出"因果层"产物**（每个单元记录：观众获得的新信息、为什么从这个单元进入下一个单元）。

 │                  │                  │
 ├→ 阶段6/7/8/11 资产库 ────────────────┤
 │                                     ↓

                                                      ↓

### 5.3 阶段号映射（关键约束）

`漫剧系统.md` §3 明确：**阶段编号是持久化 ID，历史编号不允许重排**。因此本方案：

| 目标层 | 涉及阶段号 | 改动方式 |
| --- | --- | --- |
| L1 故事层 | 1 / 2 / 3 | 阶段号全保留，仅改执行方式与产出结构 |
| L2 连续性层 | 无 | **不占阶段号**，作为阶段 3 的产出扩展 + 阶段 4 的强输入 |
| L3 资产层 | 6 / 7 / 8 / 11 | 保留，追加字段与关键帧子表 |
| L4 分镜层 | 4 / 5 | 保留，追加字段 |
| L5 提示词层 | 9 / 10 | 保留，追加状态字段与后期清单 |

结论：**零阶段号变更**。UI 上的阶段列表、进度日志、`StageProgressLogs` 全部不受影响，前端无需大改。

## 六、L2 连续性层字段草案

这是整个改造的地基，独立于其他改动，定完即可先注入阶段 4 见效。

### 6.1 场景空间表

| 字段 | 说明 |
| --- | --- |
| `scene_id` | 关联环境资产 |
| `left` / `right` | 画面左/右是什么、有什么固定物 |
| `mid_back` | 中后方是什么 |
| `foreground` | 前景是什么 |
| `entrance` / `exit` | 入口 / 出口 |
| `danger_direction` | 危险来源方向 |
| `escape_direction` | 逃生方向 |
| `action_axis` | 动作轴线（A/B 位置关系） |
| `fixed_props` | 固定道具及其位置 |
| `forbidden_changes` | 禁止改变的空间关系 |

### 6.2 道具状态 timeline

```json
{
  "prop_id": "prop_knife",
  "states": [
    { "at": "unit_1", "state": "持在右手" },
    { "at": "unit_3", "state": "落地" },
    { "at": "unit_5", "state": "被踢远" }
  ],
  "forbidden": ["unit_3 之后不得再出现在手中"],
  "must_appear": ["unit_1", "unit_3"]
}
```

### 6.3 线索揭示表

| 字段 | 说明 |
| --- | --- |
| `clue_id` | 关联道具/线索资产 |
| `reveal_order` | 第几个被揭示 |
| `reveal_at` | 在哪个单元揭示 |
| `audience_must_notice` | 观众必须注意到的具体内容 |
| `must_not_reveal_before` | 禁止提前出现 |

### 6.4 角色连续性 / 转场动机

- 角色连续性：在现有角色卡上追加 `forbidden_changes`（如"本单元不得换装""右手血迹不得超过 unit_4"）。
- 转场动机：每个衔接点标注动机类型 —— `声音桥` / `视线` / `动作` / `信息问题` / `空间`。

## 八、风险与边界

- **不引入阶段号变更**：阶段编号是持久化 ID，本方案不新增、不重排，进度与阶段体系零影响。
- 前端**只新增入口与只读页**（`continuity.html`），不改动既有页面的任何逻辑，也不新增写接口——连续性表的产出路径只有抽取一条，人工编辑暂不开放。
- **不推翻现有资产层与守卫链**，这是在现状优势上"补中间"。
- L2 连续性层会**增加 LLM 调用与 Token 消耗**，需评估是否与现有阶段 3 合并调用（推荐合并，边际成本低）。
- 关键帧层与现有"资产卡出图"是**两条不同产线**：资产卡是"一个资产一张"，关键帧是"一个剧情节点一张"。当前实现里关键帧**只做方案层**（构图 + 锁定项 + 图像提示词），不进入 `AssetImageTasks` 出图队列、也不写 `FrameAssetBindings`；后续若要真正出图并作为参考图回灌，需另开一期（会牵动出图队列与资产绑定，不适合与本次阶段测试混在一起）。
- 关键帧是**人工触发**：不点生成按钮，`ProjectKeyframes` 为空，阶段 9 的提示词与改动前逐字一致——即关键帧层本身不会给现有阶段测试引入回归。
- 后期叠加与质感层是**纯提示词层**改动：不新增输出字段行（避免破坏 `SeedancePromptParser` 与既有 `PromptRefLineGuard` 等守卫的解析契约），只把约束写进「约束：」行、把质感锚点写进既有行。
- 对标对象是**单集级**，本方案是**整季级**：L2 的连续性表需要支持跨集延续（如道具在第 3 集落地、第 5 集仍在原地），字段设计需预留 `episode` 维度。
