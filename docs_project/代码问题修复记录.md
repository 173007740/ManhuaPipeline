## 2026-09-10：ComfyUI 服务器与本地连接（地址/隧道）问题（排查手册）

问题主体是**生成服务器上的 ComfyUI 与本地项目之间的连接**；在页面上的表现是"视频没下载到本地"。

### 现象

- ComfyUI 服务器上视频**已经生成**（output 目录里有 mp4）。
- 本地表现为"没有下载到本地"：页面任务长期停在"生成中"，`VideoGenerationTasks` 里 `LocalVideoUrl` 为空。
- 容易误判成"下载代码有 bug"，实际根因是 **ComfyUI 地址不通**。

### 根因

`LLMConfigs` 表 `Provider='comfyui'` 的 `ApiUrl` 曾经指向 featurize 上的反向代理隧道，隧道断开即全部失效：

```
https://hr296z4jpyo0.proxy.featurize.cn/     ← 错误值（代理隧道，会失效）
http://127.0.0.1:8188/                       ← 正确值（本机直连，用这个就没事）
```

ComfyUI 实际启动参数是 `--port 28490`（服务端真实端口），本机 8188 是映射/隧道端口。
**配置里填能通的那个即可，实践结论是 `http://127.0.0.1:8188/`。**

### 为什么表现为"永远卡在生成中"而不是报错

`ComfyService.QueryTaskByTaskId` 请求异常时 catch 后返回 `"unknown"`：

```csharp
catch (Exception ex) { _logger.LogWarning(ex, "[ComfyService] Query error"); return ("unknown", null, ex.Message, null, null, null); }
```

而 `VideoPollingService` 只处理 `completed` / `failed`，`unknown` 不做任何状态变更
→ 任务既不前进也不失败，**永久停在 processing**，视频自然不会下载。

### 三步定位（下次直接照做，不用重新推）

1. 查配置地址（连接串取自 `ManhuaPipeline/appsettings.json`）：

```powershell
$cs="Server=.;Database=ManhuaPipeline;User Id=ManhuaApp1;Password=********;TrustServerCertificate=True;"
# SELECT ConfigId, UserId, Provider, ApiUrl, IsActive FROM LLMConfigs WHERE Provider='comfyui'
```

2. 直接打那个地址，看是否存活：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8188/system_stats' -TimeoutSec 20
```

3. 模拟"产物发现 + 下载"，确认全链路（`/history` 取 outputs → `/view` 拉字节）：

```powershell
$h = Invoke-RestMethod 'http://127.0.0.1:8188/history?max_items=20' -TimeoutSec 30
# 从 outputs 的 videos/images 取 filename/subfolder/type，拼 /view 下载，能拿到字节即链路正常
```

三条都通 → 代码没问题，等 ≥60 秒轮询即可完成下载。

### 涉及代码位置

| 位置 | 作用 |
|---|---|
| `VideoController.GetComfyBaseUrl()` | 提交任务时取地址，缺省 `http://127.0.0.1:8188` |
| `VideoPollingService`（`Task.Delay(TimeSpan.FromSeconds(60))`） | 后台轮询，**间隔 60 秒** |
| `ComfyService.SubmitTask` | `POST {baseUrl}/prompt`，参考图 `POST {baseUrl}/upload/image` |
| `ComfyService.QueryTaskByTaskId` | `GET {baseUrl}/history/{prompt_id}` |
| `ComfyService.FindOutputFile` | 拼 `{baseUrl}/view?filename=..&subfolder=..&type=..` |
| `ComfyService.DownloadVideoToLocal` | 存到 `wwwroot/uploads/videos/{projectId}/` |

### 关键结论（不要重复踩）

- **ComfyUI 配置正确值就是 `http://127.0.0.1:8188/`**；不要填 featurize 代理地址，也不要填 28490。
- 轮询间隔 60 秒，提交后至少等 1 分钟才可能看到下载，**不是"没下载"**。
- ComfyUI 重启会清空 `/history`。在跑的任务如果 `/history/{id}` 查不到，会永久停在 processing
  （实例：`VideoGenerationTasks Id=1688`，`prompt_id=70792b64-0e8b-46b0-a06e-e5aaecc91fdd`），需手工标 `failed`。
- 不要和另一类无关故障混淆：曾有 3 条失败是服务器缺权重 `minimax_h3_audio_vae_fp32.safetensors`
  （`VAELoader` 报错），那是权重文件缺失，**与地址/隧道无关**。
- 服务器 4 份工作流：`video_minimax_h3_r2v`（项目在用）/ `video_minimax_h3_i2v` / `video_minimax_h3_t2v` / `video_wan2_2_14B_animate`。

## 2026-09-10（二）：Featurize 实例重建后重连 ComfyUI（实操）

### 背景

关掉实例后重新开了一个新实例，本地 `http://127.0.0.1:8188/` 直接**拒绝连接**——隧道随实例一起没了。

### 结论（先看这段）

- **换实例后 SSH 端口和密码都会变**：本次 SSH 端口 `63542`（上一个实例是 `34632`）。
  问题不在"配置里的地址"，而是**本地 SSH 隧道要重新指向新实例**。
- **磁盘是沿用的**：`/home/featurize/ComfyUI` 下 `output/video`（当天 9 个 mp4）、`userdata/workflows`（4 份工作流）、
  权重、日志**全都还在**；只有 ComfyUI 进程内的队列与 `/history` 丢了。
  → 产物没丢，**先去 `output/video` 找**；但文件名无法反查 `prompt_id`，只能人工判断归属。
- **项目侧配置不用改**：`LLMConfigs.Provider='comfyui'.ApiUrl` 仍是 `http://127.0.0.1:8188/`
  （本地端口没变，变的是隧道另一端）。

### 更新隧道的三步

1. 改 `C:\Users\power\.ssh\featurize_askpass.cmd` 里的密码。
2. 改 `C:\Users\power\.ssh\featurize_tunnel.cmd` 里的 `-p` 端口。
3. 杀掉旧隧道进程 → 运行 `featurize_tunnel.cmd` → 用 `Invoke-RestMethod 'http://127.0.0.1:8188/system_stats'` 验证。

细节与坑见 `漫剧系统.md` §15「SSH 隧道连接细节」。

### 走过的弯路（别重复）

1. **想改用 SSH 密钥做免密，结果白折腾一轮**：`ssh-keygen -t ed25519 -N '""'` 在 PowerShell 下会把口令设成
   **字面两个引号**，生成的是**加密私钥**；`BatchMode=yes` 下无法签名，服务端日志表现为
   `Server accepts key` 紧接着 `Permission denied`——极易误判成"公钥没配对"。
   本项目实际一直用的是**密码 + askpass** 方案，现有 `featurize_comfy` 密钥同样是加密的，本来就没在起作用。
2. **服务端 sshd 的 `AuthorizedKeysFile` 被改过**，真实路径是 `/home/featurize/work/.ssh/authorized_keys`；
   往默认的 `~/.ssh/authorized_keys` 追加公钥**不会生效**。
3. **`~/work` 是 NFS 挂载且基本是空的**，不要把它当产物目录。
4. 隧道必须跑 `featurize_tunnel.cmd`（它负责 `set SSH_ASKPASS`），手敲 `ssh` 拿不到密码会一直等输入。
5. 日志只记耗时与模型加载，**不记文件名和 prompt_id**；`comfyui.db` 只有资产表、没有 history 表。
   所以**没有可靠的"按任务补下载"手段**，只能按时间/内容人工判断。

### 复盘的真正教训（重要）

上面「走过的弯路」占了那次换实例的**绝大部分时间**，而正解只有三步。**根因是方向错了**：
把"换实例"当成"配 SSH 免密"来做，于是去折腾密钥、去查 sshd 配置，全部是无用功。
**跨实例连接问题，先按"重连隧道"处理，3 步内必须能通；通不了再去怀疑认证机制。**

代价量化与改进（同日完成）：

- 那次耗时主要来自两类无效操作：① 密钥免密试探（含服务端 sshd 排查）；② 手敲 `ssh` 等密码输入卡到超时。
- 已把流程压成一条命令 `C:\Users\power\.ssh\featurize_reconnect.ps1`（见 `漫剧系统.md` §15），
  实测 **约 4 秒**完成"换端口/改密码/重建隧道/验证"。
- 新脚本内置**先试登录再动隧道**：密码或端口错时 ~1 秒报错退出，**不会杀正在跑的隧道、也不改任何文件**。
- **踩坑记录（写脚本时自己踩的）**：askpass 文件第 2 行必须是 `echo <密码>`。
  生成时若漏掉 `echo` 写成裸密码，cmd 会把它当**命令**执行，ssh 收到的是
  `'xxx' is not recognized as an internal or external command` 而不是密码，表现为
  `Permission denied (publickey,password)`——看起来极像"密码错了"，实际是 askpass 写错。

- 队列服务 `AssetImageQueueService`（`BackgroundService`）：默认并发 3，配置键 `AssetImageQueue:MaxConcurrency`（钳制 1~8）；启动时回收上次被中断的任务；乐观更新抢单；停机时把执行中的任务释放回 `queued`。
- 执行体 `AssetImageRunner.GenerateAsync`：同步接口与队列共用，不依赖 `HttpContext`。

**2. 文生图适配（`ImageService`）**

- 地址归一：只填域名自动补 `/v1`，粘完整 endpoint 也能识别。
- 接口形态不挑：主路径 `/images/generations`，遇 404/405 自动回退 `/chat/completions`（兼容 gpt-image-1 / seedream / gemini-image 这类中转）。
- 响应解析：b64_json / data-uri / url 三种都能取，按魔数推断扩展名。
- `HttpClient` 超时放宽到 10 分钟（中转站高峰排队久）。

**3. 出图提示词**

- 组成：资产名 + 描述 + 属性（角色卡）+ 项目画风（`VideoStyles.StylePrompt`）+ 类型固定要求（角色=单人全身纯色背景、场景=无人物空镜、道具=单体居中）。
- **「角色别名：xxx」这类行会被丢弃**——别名只服务 Stage 9 的 `[资产名]` 文本绑定，送进图像模型会被当成“要画出来的文字”。
- 卡片弹窗里可临时覆盖提示词（`promptOverride` / `negativeOverride`）后再出图。

**4. 落盘与回填**

- 路径 `wwwroot/uploads/images/{projectId}/{资产名}_{时间戳}{ext}`，写回资产卡既有的 `ImageUrl` 字段，**不需要改表**。

**5. 参考图库同步（本轮重点调整）**

生成图会**额外**存一份进 `ReferenceAssets`——因为视频真正吃的是 `SeedancePrompts.ReferenceImages`，它按「我的资产」图库的文件名匹配资产名，不同步等于白出。

- `FileName` = 资产名 + 扩展名（沿用，供上面的文件名匹配）。
- `Tags` = **当前项目名称**（原先是内部的 `自动出图,类型:assetId` 标记）。
- `Category`（图库「类型」，动漫/真人/游戏/仙侠）= **项目上设置的资产库类型**（`Projects.LibraryCategory`），未设置则回退成子类型。
- `SubCategory` = 角色 / 道具 / 环境 / 特效（不变）。
- 重新出图改为按 `SourceKey`（`asset:{projectId}:{category}:{assetId}`）精确替换上一次自动生成的同卡图；手动上传的图没有来源标记，不会被误删。
- 历史数据兼容：早期自动出图记录没有 `SourceKey`，按「自动出图」标签 + 文件名匹配清理一次，避免重新出图后新旧各留一张。

**6. 修掉图库「类型」一直是错的**

原实现把 `Category` 和 `SubCategory` **都**填成了“角色/道具/环境/特效”，所以图库「类型」（动漫/真人/游戏/仙侠）从来没被正确写入，看起来像“类型没有”。
改为：类型取项目设置、子类型取资产分类，各归各位。

**7. 项目「资产库类型」设置**

- 新增 `Projects.LibraryCategory`（可空，≤50 字）。
- 接口 `PUT api/project/{id}/library-category`，传空 = 清除（回退子类型）。
- 前端入口：项目页 → 提示词页顶部「⚙️ 视频参数」条 → 「资产库类型」下拉（未设置 / 动漫 / 真人 / 游戏 / 仙侠），随改随存。

**8. 前端交互**

- 每张卡右侧「出图 / 重新出图」按钮（`assetGenImg_<assetId>`）+ 状态位（`assetImgState_<assetId>`）：排队中 / 出图中 Ns / 失败可重试。
- 分类工具栏「批量出图」（`scope=missing`）与「补齐缺失提示词」。
- `pollAssetImageTasks` 每 3 秒轮询任务列表，完成后自动刷新卡片。
- 资产区顶部显示一次「本剧画风」（名称 + 提示词全文）：画风全剧统一，不再在每张卡片/每条提示词里重复展示。
- 卡片右侧图片列加 `align-self:center`，相对整卡垂直居中（左侧文字仍顶部对齐）。

### 后续注意

- `ImageServiceTests.DefaultSizeFor_UsesWideSizeOnlyForScenesAndEffects` 的期望值（角色/道具 `1024x1024`、环境/特效 `1280x720`）与现行实现已不一致：`ImageService.DefaultSizeFor` 现在四类统一返回 `1280x720`，该用例需校准。
- 出图依赖“图库文件名 = 资产名”这一约定（与参考图自动绑定同源）：**资产改名后旧的自动生成图文件名不会跟着改**，会匹配不上，需要重新出图；两个不同资产重名会互相串图。
- `AssetImageSupport` / `AssetImageRunner` / `AssetImageQueueService` 目前没有单测，队列的抢单与停机回收建议后续补用例。

- 出图提示词不含分镜上下文，同一资产在不同镜头的光影/构图差异仍只能靠视频侧提示词控制。
