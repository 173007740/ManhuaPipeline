# 战斗段落骨架设计

> 状态：设计讨论稿，未动代码
> 状态：已落地 V1（FightArcTemplates 数据模板 + 导演层 FightSequence 输出）
> 日期：2026-08-21
> 目标：让打斗戏具备完整的段落节奏，而不是“两个人挥一拳加一个特效就结束”。

## 1. 背景

现有流水线已经能生成分镜、技能、参考图和提示词，但打斗戏仍然“儿戏”。核心原因是缺少两层结构：

1. **战斗段落总谱**：一整场架怎么打（对峙 → 对话动机 → 接触战 → 缠斗 → 升级大招 → 对轰 → 分胜负 → 切场）。
2. **单镜头节拍链**：段落里的每一个镜头，如何按秒展开完整攻防（突进 → 攻击 → 闪避 → 反击 → 命中 → 受击反馈）。

当前分镜的镜头时间轴大多是 `0-2s / 2-4s / 4-5s` 的粗粒度描述；Stage 9 对 5 秒打斗只输出一个时间段，一段文字装不下完整回合链，LLM 就会偷懒成“挥一圈 + 一个特效”。

## 2. 两层结构

```text
战斗段落总谱（一场架）
├─ 阶段1 对峙进场：A 特写 / B 特写 / 双人同框
├─ 阶段2 对话动机：为什么打、情绪、条件
├─ 阶段3 接触战：跟拍脚步、双方飞速对撞
├─ 阶段4 缠斗：多镜头连续交锋（地面/空中，2-4 回合/镜）
├─ 阶段5 升级：双方放大招、技能描述入台词
├─ 阶段6 大招对轰：景别拉开、特效峰值
├─ 阶段7 分胜负：一人倒下/被压制，定格收尾
└─ 阶段8 切场：接下一场戏

单镜头节拍链（一个镜头）
└─ 0-1s 突进 → 1-2s 攻击 → 2-3s 闪避 → 3-4s 反击蓄力 → 4-5s 命中收尾
```

## 3. 段落骨架类型

不搞一套模板套所有打斗，按剧本内容选择：

| 骨架 | 阶段 | 适用场景 |
| --- | --- | --- |
| 完整对决 | 对峙 → 对话 → 接触 → 缠斗 → 升级 → 对轰 → 胜负 → 切场 | 主要角色、高潮对决 |
| 遭遇战 | 警觉 → 对冲 → 快速交锋 → 短暂胜负 → 脱战 | 中途遇敌、小冲突 |
| 偷袭/速杀 | 潜伏 → 突进 → 一击命中 → 环境反应 → 切场 | 暗杀、秒杀、一击制胜 |
| 围杀/突围 | 合围 → 轮攻 → 硬抗 → 破局大招 → 反杀/撤离 | 以少敌多、阵法围困 |
| 追逐战 | 追逃 → 地形变化 → 拦截 → 正面交锋 → 再逃/停下 | 追击、逃亡、赶路冲突 |
| 文戏对峙 | 对峙 → 言语交锋 → 单次冲突 → 被制止/各自退场 | 不下死手的冲突、装逼对峙 |

## 4. 段落级字段

每个阶段（Phase）必须锁定：

- `phase`：阶段名
- `purpose`：本阶段情绪/叙事目的
- `durationBudget`：预计时长占比或秒数
- `shotCount`：镜头数量
- `shotStyle`：景别策略（特写/全景/大远景）
- `camera`：运镜策略（缓推/跟拍/快切/环绕/震动跟随）
- `vfxLevel`：特效强度 0-100%（保证大招对轰是峰值）
- `skills`：本阶段允许的技能（大招前有蓄力与台词）
- `dialogue`：本阶段台词/情绪
- `endState`：双方站位、距离、朝向、伤势、气血、武器、环境破坏状态
- `nextCondition`：与下一阶段的衔接条件

## 5. 节奏曲线

打斗段落的统一节奏口诀：**铺垫慢 → 试探中 → 缠斗快 → 变招顿 → 大招重 → 胜负定格 → 余韵缓**。

- 对峙/对话：稳定缓推，特写为主
- 接触战：跟拍，脚步与加速感
- 缠斗：高速快切，回合密集
- 升级：蓄力停顿，镜头拉开
- 对轰：极重定格 + 慢动作（0.2-0.4s），禁止全程慢放
- 胜负：定格收尾，留情绪余韵

## 6. 单镜头节拍链规范

只对打斗/高潮镜头启用：

- 5 秒镜头：默认 `0-1s / 1-2s / 2-3s / 3-4s / 4-5s` 五拍；内容不足可合并为 `0-2s / 2-4s / 4-5s`，禁止只写单段。
- 11 秒镜头：`0-2s / 2-4s / 4-6s / 6-8s / 8-11s` 五段。
- 15 秒镜头：`0-3s / 3-6s / 6-9s / 9-12s / 12-15s` 五段。
- 每段必须同时有：双方动作、镜头运动、命中/受击反馈。
- 每镜节拍必须接上一镜结束画面，禁止无来源瞬移。

## 7. 补充规则

1. **回合预算按总时长算**：5 秒最多 3 个完整攻防；11 秒 4-5 个；15 秒 5-6 个。“几十回合”由缠斗阶段多镜头连续打 + 快速剪辑实现，禁止在单个 5 秒镜头里塞几十拳。
2. **镜头间状态不跳变**：记录双方位置/朝向/伤势，下一镜必须接得上。
3. **每拍都有对位**：A 攻什么、B 怎么防/反击、命中后 B 什么反应，禁止独角戏。
4. **VFX 克制与峰值**：前期只给接触感和轻微光效，大招阶段才拉满；禁止每镜全程特效。
5. **胜负要有代价**：赢了不能白赢（受伤、金身崩碎、法宝损坏、为下单元埋线）。
6. **场景破坏递增**：地面裂纹 → 碎石 → 山壁崩穿 → 场景重构，破坏程度是升级标尺。
7. **对峙/对话对称镜头**：A 特写、B 特写、双人同框都要有，先立住对手再开打。
8. **成本控制**：拆秒只用于打斗/高潮镜头，文戏保持单段；每段字数设上限。
9. **技能归属与层级**：大招按 T3/T4/T5 阶段使用，大招前必须有蓄力/台词；技能归属角色必须出场。
10. **校验器**：检查阶段完整性、回合数、技能归属、胜负落点、镜头衔接、VFX 峰值不越级。

## 8. 与现有流程的接入点

- **导演层**：对打斗单元输出“战斗段落”结构（`FightSequence`），作为分镜生成的输入。
- **分镜（Stage 5）**：按段落阶段生成镜头，镜头携带 `PhaseId`、时间轴、节拍链、双方状态快照。
- **Stage 9**：打斗镜头按节拍拆时间片输出；后置守护继续负责技能参考图、战斗态双卡、台词、时间轴归一。
- **资产/技能库**：不变，仍按标签与归属过滤。
- **前端**：分镜页面可展示段落阶段、节拍链、VFX 曲线。

## 9. 数据模型建议

```text
FightSequences
- FightSequenceId
- ProjectId / EpisodeId / UnitRange
- ArcType          # 骨架类型
- TotalDuration
- Winner           # 胜负落点
- PhasesJson       # 阶段数组（含字段见第 4 节）
- Status
- CreatedAt

StoryboardFrames 增加
- PhaseId          # 所属战斗阶段
- BeatChainJson    # 单镜头节拍链
- EndStateJson     # 镜头结束状态快照
```

## 10. 落地顺序

1. 先写骨架模板和阶段 JSON 定义（本文档作为基准）。
2. 导演层对打斗单元输出战斗段落（不碰文戏）。
3. 分镜按阶段生成镜头并锁定衔接状态。
4. Stage 9 打斗镜头按节拍拆秒。
5. 加校验器与 A/B 开关：同一段分镜分别用旧流程和新流程生成，对比视频效果。

每一步可单独验证，尽量不影响文戏和其他项目的现有流程。
